Wikimedia › Headshots

Everything stays on this device. Photos are read from the folder you pick and renamed in place. No upload, no account, nothing sent anywhere — the badge reading uses a model built into Chrome. The one exception is the Wikipedia look-up at the end, which only happens when you press its button.

1

Set up this device

Everything this needs is settled here, before you start, so nothing interrupts you halfway through a shoot. The two downloads come from this site and are kept in this browser; the model belongs to Chrome. Do this once on each machine — after that the tool works offline.

2

Pick the shoot folder

The folder of photos straight off the camera. Chrome will ask permission to edit it — that is what lets the photos be renamed in place.

3

Add a programme or delegate list

optional

A PDF, a screenshot, or exported pages — anything that puts photographs next to printed names. Every face is found and the name printed with it is picked up, giving a list of people this shoot can be matched against. That covers a missed badge, and shoots with no badges at all.

The model does the matching; it is not allowed to invent a name. The names themselves are taken from the document's own text, exactly as printed, and the model is then shown each face and asked which of those names belongs to it — it can only pick from the list or say nobody. Position is worked out separately as a cross-check, and any face where the two disagree is flagged for you.

The layout is read off the page rather than assumed, so names may sit under, beside or above the photographs, in any script, and job titles printed with them are not mistaken for people. A scan or screenshot has no text to take names from, so there the model has to read them and they are marked unverified.

PDFs are rendered on this device. Only embedded fonts are available, so if a page comes out garbled, export it as an image and add that instead — bearing in mind an image's names are read by the model, not taken from the page, so they need checking.

4

Check who is who

Reading the folder finds the badges and compares the faces by itself — there is nothing to start. One card per person, in the order they were photographed. Correct a name by typing in it.

A badge starts a new person and is outlined in blue. Where nobody wore one, a change of face starts the next person instead. If a frame was taken for a badge, or missed as one, use badge / not a badge and the people are worked out again.

Compares each person's headshots with one another, so a face that does not belong shows up. It only flags photos for you to look at — it never regroups or files anything.

Rename and file

Named people only. Their photos move into a done folder as Name Surname 01.jpg; anything unnamed, and anything before the first badge, is left exactly where it is.

About this tool

      
    

    
Filing a few hundred event headshots by hand is slow and easy to get wrong.
    This does the matching from what the photographer already does: shoot the
    badge, then the person.

    
How to shoot for it

    
    
      
  1. Photograph the person's badge, name card, or a phone or
        laptop screen showing their details — one frame is enough.
    2. 
      
  2. Photograph the person, as many frames as you like.
    3. 
      
  3. Next person: badge, then person. And so on.
    4. 
    

    
Everything between one badge and the next is treated as that person. A
    badge the model can't read still starts a new person — it just needs a name
    typing in, so photos never get filed under the person before.

    
Badges are optional. Some people will be shot without one.
    Where no badge separates two people, a change of face does — the subject
    changing is the thing actually being detected, so there is no interval to
    guess at. Reading the folder does all of this by itself. Nothing is filed
    until you have confirmed the people in step 4.

    
Using a programme instead of badges

    
If you have a PDF or screenshot pairing photographs with names, add it in
    step 3. Each face on the page is found, and the name that goes with it is
    settled in two independent ways: the names are taken verbatim from the
    document's own text, and the on-device model is shown each face and asked
    which of those names it belongs to, picking from that list only. Where the
    model's answer and the printed position disagree, the face is flagged for you
    rather than guessed at.

    
Name them from the document in step 4 then matches anyone still
    unnamed by comparing faces, so a shoot with no badges at all can still be
    filed. It proposes and shows its score; you confirm. PDF pages are rendered on
    this device with Mozilla's pdf.js from our vendored copy; images need no
    download.


    
What it needs

    
    
      
  • Chrome or Edge on a desktop. Renaming files in your own
        folder uses the File System Access API, which Firefox and Safari do not
        have, on any platform.
    • 
      
  • Chrome 148 or newer for the built-in model (Edge has it
        only behind a flag). Step 1 checks for it, fetches it and warms it up, so
        you find out before a shoot rather than during one.
        Per Google's requirements that means Windows 10/11,
        macOS 13+, Linux or a Chromebook Plus, 22 GB free on the drive holding
        your Chrome profile, and either more than 4 GB of VRAM or 16 GB of RAM
        with 4+ cores. There is no mobile support. The model downloads once, on
        first use, and is Chrome's — not ours.
    • 
      
  • Times come from each photo's EXIF capture time, falling
        back to the file's date for screenshots and PNGs. Only the order matters,
        so the camera's clock being off is harmless.
    • 
    

    
Privacy

    
    
      
  • Photos are read from the folder you choose and renamed there. Nothing is
        uploaded, and the page has no analytics.
    • 
      
  • Names and small thumbnails are kept in this browser's own storage so you
        can close the tab mid-shoot. Forget this shoot clears them.
    • 
      
  • The model runs on your device; Chrome's documentation states no data is
        sent to Google or any third party when using it.
    • 
      
  • The Wikipedia look-up sends only the names, and only when you press it.
    • 
    

    
Checks

    
Open the checks page to see what this browser
    supports and to self-test the renaming on throwaway files.

    
Limits

    
    
      
  • It reads what is written on a badge to get a name. It never identifies
        anyone from their appearance, and matches nothing against any database
        of people.
    • 
      
  • The face check only asks "do these photos look like the
        same person?", within one shoot, to catch a missed badge. Measured on one
        event's photos: same person 0.61–0.97, different people 0.17–0.48, so a
        score under 0.55 is flagged. The margin is thinnest in group shots, where
        the biggest face may not be the subject — which is why it flags rather
        than decides. It needs about 19 MB of MediaPipe, downloaded from this site
        once, with every file checked against its SHA-256.
    • 
      
  • Photos before the first person have nobody to attribute them to until
        you name them — they are left alone.
    • 
      
  • This is new. Check the people in step 4 before filing.
